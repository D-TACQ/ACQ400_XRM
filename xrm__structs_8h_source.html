121/** @brief SOE_HOLD_TABLE
122 - This is the OUTPUT from each CYCLE
123
124 - For N events, the OUTPUT comprises:
125
126 1. N+1 SOE_HOLD_HEADER rows, headers for N events + 1 row of zeros (DELIMITER)
127 2. N RAW SAMPLE rows
128
129 - The HEADER includes the geometry of the raw sample entries, so the data is self-describing.
130
131 - The RAW SAMPLE row varies per unit type, the fixed header includes info to access the RAW SAMPLE.
132
133 - We prefer to offer the RAW sample because
134
135 + Blitting off a row of data is our most efficient transfer
136 + No conversion to EGU's. User to do that thanks to $UUT:*:EOFF,ESLO
137 + RAW sample includes METADATA for checking purposes.
138
139 - To interpret a received HOLD DATA:
140
141 + iterate the SOE_HOLD_HEADER rows until zero
142
143 + use data_offset to access the data.
144
145 - In summary, the memory layout looks like this:
146
147 ROW | pv_id | client_data | timestamp | data_offset | ss_u32 | ai_count | di_count | sp_count
148------|-------|-------------|-----------|-------------|--------|----------|----------|---------
149 0 | u32 | u32 | int64 | u16 | u8 | u8 | u8 | u8
150 1 | u32 | u32 | int64 | u16 | u8 | u8 | u8 | u8
151 ... | u32 | u32 | int64 | u16 | u8 | u8 | u8 | u8
152 DEL | 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0
153
154 RAW | ai | di | sp
155 -----|----|----|---
156 R0 | i16|u32 |U32
157 R1 | i16|u32 |U32
158
159
160```
161 Example 4 entries
162 sizeof(SOE_HOLD_HEADER==22)
163 XRMMAGPS: SSB=128 ruler in byte*2:
164 00000111112222233333444445555566666777778888899999AAAAABBBBBCCCC
165 0246802468024680246802468024680246802468024680246802468024680246
166 |SOE HOLD 1 |
167 |SOE HOLD 2 |
168 |SOE HOLD 3 |
169 |SOE HOLD 4 |
170 |00000000000|
171 |RAW SMPL 1 AIAIAIAIAIAIAIAIAIAIAIDIDISPSPSPSPSPSPSPSPSPSPSPSPSP|
172 |RAW SMPL 2 AIAIAIAIAIAIAIAIAIAIAIDIDISPSPSPSPSPSPSPSPSPSPSPSPSP|
173 |RAW SMPL 3 AIAIAIAIAIAIAIAIAIAIAIDIDISPSPSPSPSPSPSPSPSPSPSPSPSP|
174 |RAW SMPL 4 AIAIAIAIAIAIAIAIAIAIAIDIDISPSPSPSPSPSPSPSPSPSPSPSPSP|
175
176
177 showing the SOE HOLD struct on a line of bytes
178 0123456789012345678901|24680246802468024680246802468024680246802468024680246
179 PVID | epicsUInt32 pv_id;
180 ____CLID______________| epicsUInt32 client_data;
181 ________TIMSTAMP______| epicsInt64 timestamp;
182 ________________DO____| epicsUInt16 data_offset;
183 __________________SADP| epicsUInt8 ss_u32, ai_count, di_count, sp_count;
184
185 ```
186
187 Actual wire protocol:
188 - We meet the letter of the requirement by sending as a PVA ARRAY of U32
189 - where NORD gives the overall size of the table, including DATA.
190
191 - In the above example, MAGPS with 4 EVENTS,
192 - NORD = (5 * sizeof(SOE_HOLD_HEADER))/sizeof(int32) + 4*SSB/sizeof(int32)
193 - NORD = (5 * 22)/4 + 128
194 - NORD = 156 @@todo 22 is not a good size for the structure..
195
196 @@todo We've attempted to meet the spirit of the requirement using the PVXS API
197 to create an Array of Groups, but this has not been a success.
198 Happy to revisit later when we have an example that works.
199 */
200typedef struct SOE_HOLD_HEADER* SOE_HOLD_TABLE; // many more than 1 of course..

203/* For data allocation, what is the MAXIMUM size of table:
204 * HOLD_MAXSIZE = 64*20+64*(128*2+16*4) = 21760B = 6400LW
205 * */
206
207static inline const int HOLD_DATA_OFF() { return (SOE_HLD_ROWS+1)*sizeof(SOE_HOLD_HEADER); };
208static inline const int HOLD_MAXSIZE(unsigned ssb) { return HOLD_DATA_OFF() + SOE_HLD_ROWS*ssb; }
209static inline const int HOLD_MAX_NELM(unsigned ssb) { return HOLD_MAXSIZE(ssb)/sizeof(long); }
